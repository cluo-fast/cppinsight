# 产品优化方案（2026-09-08）

基线：codex/graph-workbench，51b334d。目标保持为免费 Windows 产品、复杂关系图首发、先改善体验再引流。

## 顺序与验收

1. **可信的修改影响调查（本轮实施）**：图中选中函数即可分析上游影响；直接/间接调用者分层、入口候选、调用链与证据可查；沿真实 calls 边遍历并处理循环，稳定 ID 区分同名函数。深度、分页、启发式边界必须展示，不能把未发现影响描述成安全可改。
2. **证据和源码联动（本轮实施）**：节点位置、关系证据可点击预览索引代码。后端校验项目作用域，只读 chunks 中的片段；展示索引时间，避免冒充当前磁盘代码；限制响应大小。
3. **大图调查体验（本轮实施基础部分）**：提供调用者/被调用者/邻域快捷入口；渐进查询保留已有节点坐标；纠正路径高亮误选旁路边的问题。后续完善模块聚合、第三方依赖识别、导航历史和调查书签。
4. **Windows 发布稳定性**：读取失败 CI 的真实日志、修复并复验，保留安装与校验和证据。单机“测试完成”与干净 runner 安装验证分别记录。
5. **真实项目质量基线**：落实既有 10 项目清单的 revision 和人工核对样本，测准确率、耗时、内存；按失败案例改解析器，不用样例项目冒充容量结果。
6. **持续使用能力**：Git 两提交差异与影响范围、调查备注/书签/阅读进度；跨索引恢复时显示失效节点，避免误导。
7. **公开测试与引流**：私有源码仓库的 Issues 不作为公众唯一反馈渠道；待确定独立反馈地址和下载渠道后接入。准备任务演示、邀请小规模真实用户验证首次体验，再完善官网/演示内容。

## 实现边界

- 复用 Graph Protocol v1 的入口图和反向 calls 查询，默认 3 层、最高 8 层、单次 500 节点。
- 影响列表只解释实际返回且与根连通的调用路径；结果截断时明确提示缩小范围，不声称覆盖全部项目。
- 影响路径中保留所有证据置信度；识别入口使用索引 entry 标记，不能把无上游的任意函数当作程序入口。
- 不改仓库可见性、版权主体、签名身份；新反馈站点、用户邀约需要真实入口/受众信息。
