# 许可证边界与发布前检查

当前仓库尚未提交根目录许可证文件，因此现阶段源码不应被描述为已经授予公众的开源许可，也不应把 Windows 桌面构建包当作具有再分发授权的正式产品。依赖包和示例项目各自的许可证仍以其上游声明为准。

## 已确认的产品方向

公开测试的长期方向是 open-core，但必须由项目所有者在发布前把授权落到仓库文件和制品说明中：

- `src/`、`tests/`、扫描器 CLI、协议文档和 `tools/mcp-server/` 是公开核心候选范围，计划采用 Apache-2.0。
- `desktop/` 包含 Windows 桌面应用和完整产品体验，当前不授予默认再分发权；如决定开源或单独授权，必须使用明确的许可证文本。
- `examples/` 中的示例源码应保留独立的版权和许可证说明，不自动继承核心许可证。

## 正式公开前必须完成

1. 确认版权主体、贡献者协议和核心许可证版本。
2. 在核心范围加入完整许可证文本、NOTICE 和必要的 SPDX 元数据。
3. 为桌面目录加入明确的专有或商业授权声明，并在安装包发布说明中同步。
4. 复核 Cytoscape.js、Tauri、Rust、Node 依赖及 10 个基准项目的再分发条件。
5. 在发布审查中记录许可证文件、制品版本和第三方声明，未完成前保持“内部/候选构建”标记。

本文件是发布审计边界，不构成法律意见；正式授权文本应由项目所有者或法律顾问确认。
