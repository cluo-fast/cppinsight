# CppInsight AI 免费公开测试版与代码关系图设计

## 状态

- 日期：2026-08-27
- 状态：产品方向与各设计章节已由用户确认
- 首发平台：Windows
- 首发目标：先完成高质量产品并获得真实用户与案例，暂不建设付费闭环

## 1. 背景与产品定位

CppInsight AI 当前已经具备 C/C++ 项目扫描、本地 SQLite 索引、符号与调用关系、项目问答、影响面分析、多项目多会话、CLI 和 MCP 等基础能力。下一阶段不应继续扩展为通用 AI 编程助手，而应围绕一个清晰任务形成完整产品：帮助开发者接手陌生、遗留或缺少文档的 C/C++ 项目。

产品采用“自动接手报告 + 交互式代码关系图”双核心：

> 用户在 Windows 上打开一个陌生 C/C++ 项目后，可以在可接受的等待时间内获得有源码证据的接手报告，并通过复杂关系图继续调查架构、调用、继承、包含和入口路径。

首批目标用户是独立顾问、外包团队和需要接手客户旧代码的开发者。首个公开版本免费使用，以完成首次索引、查看报告与关系图、再次使用和主动反馈作为主要成功指标。

## 2. 目标与非目标

### 2.1 目标

1. 提供可安装、可更新、稳定运行的 Windows 桌面应用。
2. 对 200 万行、约 20,000 个源码文件的项目完成可用的本地分析。
3. 自动生成结构化《项目接手报告》，每条关键结论保留源码证据与置信度。
4. 首发交付模块依赖、函数调用、类关系、文件包含和入口执行路径五类交互图。
5. 报告、关系图、符号分析和 AI 问答共用同一份本地索引并双向跳转。
6. 公开扫描核心、CLI、MCP 和协议，通过开源内容为免费桌面测试版引流。
7. 用公开基准项目持续衡量准确率、性能和回归。

### 2.2 非目标

1. 不替代 Visual Studio、CLion 等完整 IDE。
2. 不以代码补全、代码生成或自动修改代码作为首发卖点。
3. 不承诺 MISRA、AUTOSAR、安全漏洞或合规审计能力。
4. 首发不实现函数内部控制流图、变量级数据流或污点传播。
5. 首发不建设账号、支付、订阅和团队协作系统。
6. 首发不提供 macOS/Linux 桌面安装包；CLI 和 MCP 保持可移植设计。
7. 不引入独立图数据库；SQLite 足以支撑首版的持久化和子图查询。

## 3. 核心用户流程

1. 用户安装并启动 CppInsight AI。
2. 用户可先打开内置示例项目，也可选择本地 C/C++ 项目目录。
3. 应用检测 CMake、Visual Studio、Makefile、`compile_commands.json` 等构建线索。
4. 应用建立本地索引，持续显示阶段、文件数、耗时、警告和取消入口。
5. 索引事务成功后，应用生成《项目接手报告》。失败或取消时继续使用上一份完整索引。
6. 用户从报告章节进入对应关系图，也可直接搜索文件、类或函数打开图谱。
7. 用户通过展开、筛选、路径分析和证据面板调查项目。
8. 用户可从节点进入符号影响分析或带检索上下文的 AI 问答。
9. 用户导出 Markdown、HTML 报告以及 PNG、SVG 关系图。
10. 用户可自愿提交不包含源码的诊断包和反馈。

## 4. 项目接手报告

首版报告包含：

- 项目规模、文件分布、语言标准和目录结构
- 构建系统、构建入口、目标和 `compile_commands.json` 状态
- 程序入口与关键执行链路
- 模块划分、模块职责及模块间依赖
- 内部依赖与第三方依赖线索
- 核心类、函数和公共接口
- 大文件、高扇入扇出、循环依赖、公共头污染等维护热点
- 解析模式、置信度、未解析关系和可能遗漏项
- 建议优先阅读的文件与符号顺序
- 新成员前 1～3 天的接手清单
- 每项关键结论对应的源码路径、行号和关系证据

报告不是一次性 AI 长文本。它由确定性索引和图查询先生成结构化事实，再由可选 AI 对事实进行摘要。没有配置模型时，用户仍可获得完整的本地基础报告。

## 5. 可视化关系图工作台

### 5.1 首发图类型

1. **模块依赖图**：展示目录或组件之间的依赖方向、依赖强度、循环依赖和核心模块。
2. **函数调用图**：从任意函数向上查看调用者、向下查看被调用者，并调整展开深度。
3. **类关系图**：展示继承、实现、组合和主要使用关系，标注模板或解析歧义。
4. **文件包含图**：展示头文件依赖、扇入扇出、循环包含和高耦合公共头文件。
5. **入口执行路径图**：从 `main`、`WinMain`、`wWinMain`、`DllMain` 和测试入口等追踪到目标符号。

### 5.2 统一交互

- 缩放、拖动、框选、搜索和小地图
- 节点展开、收起及调用深度控制
- 按模块、文件、符号类型、关系类型和置信度筛选
- 自动布局与用户手动调整布局
- 高亮最短路径、循环依赖和关键节点
- 点击节点查看定义、引用、源码位置、关系证据和置信度
- 从节点直接进入“查符号”或“问 AI”
- 报告章节与图谱视图双向跳转
- 导出 PNG、SVG，并在 HTML 报告中嵌入静态图
- 大图默认聚合，按需渐进展开

### 5.3 图形引擎

首版采用 Cytoscape.js。它负责画布交互、样式、图算法调用和布局扩展。默认策略如下：

- 模块和包含关系优先使用层次布局（Dagre 或 ELK）。
- 调用、类关系和局部影响网络优先使用 fCoSE。
- 布局在 Web Worker 或异步任务中执行，不能阻塞主界面。
- 前端默认最多展示约 500 个可见节点；超过限制时请求后端聚合或更小子图。
- 首版不同时维护 Sigma.js 等第二套渲染引擎。

## 6. 系统架构

### 6.1 C++ 分析核心

C++ 核心负责从源码和构建配置提取基础事实，不生成产品文案，也不依赖桌面界面：

- 文件、模块、包含关系和构建线索
- 类、函数、定义、声明和限定名称
- 调用位置、所属调用函数及候选目标
- 继承、组合和主要使用关系
- 程序和测试入口
- 源码位置、解析模式、诊断和置信度

实体必须具有在项目路径和内容未改变时保持稳定的 ID。所有关系必须保留证据位置。启发式分析与基于完整编译数据库的语义分析必须在结果中明确区分。

### 6.2 Rust 索引与图查询服务

Rust/Tauri 后端作为索引事务、关系解析和图查询边界。它负责：

- 将扫描结果规范化写入项目本地 SQLite
- 解析调用目标和类关系，保留歧义候选
- 生成模块依赖、循环依赖和图统计
- 查询指定方向、深度和筛选条件的子图
- 计算入口路径、最短路径、环和关键节点
- 按目录、文件或符号聚合节点
- 实施节点上限，返回截断原因和原始规模
- 为报告、图谱和 AI 检索提供同一套查询服务

现有 `desktop/src-tauri/src/lib.rs` 应在实现过程中按职责拆分为索引、图查询、报告和 AI 模块。该拆分只服务于本设计，不进行无关重构。

### 6.3 SQLite 数据演进

保留现有 `projects`、`files`、`symbols`、`includes`、`calls` 和 `chunks` 等事实表，通过迁移增加：

- 符号稳定键、限定名称和父级实体引用
- 调用来源符号、已解析目标符号及候选目标
- `symbol_relations`：calls、inherits、implements、contains、uses 等关系
- `module_relations`：聚合后的模块依赖和权重
- `graph_layouts`：按项目、图类型和视图键保存用户调整的位置
- 索引 schema 版本、生成器版本及最后完整事务标记

数据库写入使用新事务构建完整索引，成功后再切换当前版本。取消、崩溃或单次失败不得破坏上一份完整索引。

### 6.4 统一图查询协议

图查询请求至少包含：

```text
project_id
graph_kind
root_node_ids
direction
depth
filters
max_nodes
path_target
```

响应至少包含：

```text
nodes
edges
groups
evidence
confidence
statistics
truncated
truncation_reason
continuation
```

协议必须版本化。桌面应用、CLI 和 MCP 可复用同一图查询模型，前端不得自行从原始表重新推导业务关系。

### 6.5 React 桌面界面

新增独立 `GraphWorkbench`，其职责限定为图谱状态和交互：

- 左侧：图类型、搜索、筛选和图例
- 中间：Cytoscape.js 关系图画布
- 右侧：节点详情、关系证据和快捷操作
- 顶部：布局、路径分析、导出和重置
- 状态区：节点数、边数、置信度和截断提示

报告页面、聊天页面和图谱通过稳定节点 ID 传递选择状态。图谱组件不直接访问 SQLite。

### 6.6 报告与 AI

报告生成器消费结构化图查询结果，每个章节保存可重新打开图谱的视图描述。AI 只接收与当前问题相关的节点、边和源码片段，并向用户显示将发送的上下文。AI 失败不影响本地索引、图谱和基础报告。

## 7. 性能与容量目标

参考环境为 8 核 CPU、16GB 内存和 SSD 的普通开发机。首个公开测试版目标：

- 200 万行、约 20,000 个源码文件的首次索引不超过 5 分钟
- 索引期间界面保持可操作并可取消
- 完整索引项目再次打开不超过 3 秒
- 不超过 100 个变更文件的增量索引不超过 30 秒
- 默认子图不超过 500 个可见节点，首次出图不超过 2 秒
- 超限图自动聚合，不能卡死或静默丢弃关系
- 峰值内存控制在 2GB 内

性能数字以公开基准机和基准仓库的重复测量为准。达不到目标时发布说明必须披露结果，不以降低数据完整性或隐藏截断换取表面速度。

## 8. 可信度、错误处理与隐私

### 8.1 可信度与降级

- 每个节点、边和报告结论携带源码证据与置信度。
- 缺少 `compile_commands.json` 时继续启发式分析，同时明确提示能力限制和改进方法。
- 单个文件失败不会中止项目；结果列出失败文件和受影响图类型。
- 未解析调用、歧义重载和模板关系使用独立样式，不伪装成确定关系。
- 图被截断时显示原因、原始规模和继续展开方式。
- 数据库损坏时提供诊断导出、备份检测和安全重建。
- 所有耗时任务支持取消；错误信息包含下一步操作。

### 8.2 安全与隐私

- 源码和图索引默认只保存在本机。
- 提供完全关闭 AI 的纯本地模式。
- 调用 AI 前显示将发送的文件和片段范围。
- API Key 存储到 Windows Credential Manager，不再明文写入 SQLite。
- 配置严格的 Tauri CSP 和最小能力权限。
- 遥测默认关闭；用户主动开启后也不采集源码、提示词和模型回答。
- 反馈诊断包默认移除绝对路径、源码内容、API Key 和个人信息，并允许用户发送前预览。

## 9. 测试与发布标准

### 9.1 自动化测试

- C++：文件扫描、构建配置、宏、模板、重载、继承、调用归属和异常文件测试
- Rust：数据库迁移、关系解析、路径、环、聚合、筛选、深度、截断和事务恢复测试
- React：筛选、展开、选中、布局切换、报告跳转、导出和错误状态测试
- 视觉回归：五类图的固定数据集截图或结构快照
- 端到端：Windows 安装、首次启动、示例项目、真实项目索引、导出、升级和卸载

### 9.2 基准集

选择至少 10 个许可允许自动测试、规模和构建体系不同的开源 C/C++ 项目。为关键符号、入口和关系维护人工核验样本。每次发布记录：

- 符号与关系准确率样本
- 未解析和歧义关系比例
- 首次与增量索引时间
- 峰值内存
- 五类图的查询和出图时间
- 与上一版本的回归变化

### 9.3 发布门槛

- C++、Rust、前端和端到端测试通过
- 性能基准无未解释的显著退化
- 自动构建 Windows 安装包并生成校验值
- 正式公开安装包完成代码签名
- 发布说明包含功能、修复、性能、已知限制和隐私变化
- 崩溃或失败能生成经过脱敏、可由用户预览的诊断包

## 10. 开放边界与仓库策略

采用 open-core 模式。

公开的 `cppinsight-core` 包含：

- C++ 扫描与索引核心
- CLI
- MCP Server
- 版本化索引格式与图查询协议
- 示例、基准和开发文档

公开核心默认采用 Apache-2.0 许可证，便于个人和企业使用，同时保留明确的贡献与专利条款。

私有的 `cppinsight-desktop` 包含：

- Windows 桌面应用
- Cytoscape.js 可视化工作台
- 自动接手报告生成器
- 项目与对话管理、自动更新和完整产品体验

核心与桌面通过版本化 JSON/命令协议通信。当前仓库若已公开，既有历史不可撤回；从拆分版本开始清晰声明新边界和许可证，不删除历史，也不暗示历史代码自动受新的私有条款约束。

## 11. 免费测试版与引流闭环

免费测试版无需登录即可使用本地扫描、五类关系图和基础报告。AI 使用用户自带 Key。应用提供示例项目、反馈入口、隐私说明、版本信息和已知限制。

引流闭环：

```text
技术文章或演示视频
→ GitHub 开源核心或 MCP
→ 下载免费 Windows 桌面版
→ 扫描自己的项目
→ 查看接手报告和关系图
→ 导出报告或分享截图
→ 提交案例、问题或建议
→ 产品改进形成下一轮内容
```

首批内容聚焦真实任务：

- 10 分钟摸清一个陌生 C++ 项目
- 从 `main` 到目标函数的完整调用路径
- 用关系图发现循环依赖和公共头文件污染
- 评估没有文档的遗留 C++ 仓库
- 为知名开源项目生成接手报告

核心指标：

- 完成首次索引的比例
- 打开报告和关系图的比例
- 一周内再次使用的比例
- 报告和关系图导出次数
- 真实项目分析失败率
- 主动提交案例和反馈的用户数

GitHub Star、下载量和视频播放量只作为流量参考，不作为产品价值的主要判断标准。

## 12. 实施阶段

1. **发布基础**：补齐安装、打包、图标、Credential Manager、CSP、Windows CI、签名和诊断能力。
2. **图数据基础**：建立稳定 ID、解析关系、置信度、迁移和统一图查询协议。
3. **图谱工作台**：依次实现模块、调用、类、包含和入口路径图，以及统一交互与大图聚合。
4. **报告融合**：完成结构化接手报告、图谱双向跳转和 Markdown/HTML/PNG/SVG 导出。
5. **质量基准**：建立 10 个开源项目的准确率、性能、内存和视觉回归体系。
6. **公开测试**：拆分开放边界，发布开源核心、免费 Windows 测试版、官网、示例和演示内容。
7. **反馈迭代**：根据激活、留存、失败率和真实案例确定后续功能与商业化时机。

每个阶段单独形成实现计划和验收，不把全部阶段合并为一次大改动。首个实施计划从“发布基础”开始。

## 13. 验收标准

公开测试版发布前必须满足：

1. 新用户能在无命令行操作的情况下安装应用并打开示例项目。
2. 用户能为真实项目完成扫描；缺少编译数据库时获得清晰降级说明。
3. 接手报告包含约定章节、源码证据、置信度和阅读建议。
4. 五类关系图均可从报告或搜索入口打开。
5. 图谱具备缩放、搜索、筛选、展开、路径分析、证据面板和导出。
6. 大图超限时聚合并清楚提示，界面不冻结。
7. 报告、图谱、符号分析和 AI 问答能围绕稳定节点 ID 双向跳转。
8. AI 关闭或调用失败时，本地分析、图谱和基础报告仍完整可用。
9. API Key 不以明文存储，诊断包不泄露源码和凭据。
10. 在约定参考环境和基准项目上达到性能目标，或在发布说明中明确披露未达项并阻止标记为正式公开测试版。
11. Windows 安装包通过自动化端到端测试、带校验值并完成代码签名。
12. 开源核心与私有桌面的仓库、协议和许可证边界清晰可验证。
